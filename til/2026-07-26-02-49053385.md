### TIL: Interactive Git Rebase Gotchas

I came across a recent article on Hacker News, "Git rebase -I is not that scary" ([https://cachebag.sh/journal/interactive-rebasing/](https://cachebag.sh/journal/interactive-rebasing/)), which highlighted some common pitfalls when using `git rebase -i`. TIL that one common mistake is not understanding the `reword` command, which can silently squash the entire commit history if not used correctly. Additionally, I learned that `git rebase -i` can be a powerful tool for rewriting commit history, but it can also be a source of frustration if not used with caution. To avoid these gotchas, I'll make sure to carefully review my commit history and use `git rebase -i` with a clear understanding of its implications.
