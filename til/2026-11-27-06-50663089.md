# TIL: The need for a formally verifiable mainstream programming language

_2026-11-27 06:23 UTC_

[Original Source](https://blainehansen.me/post/mainstream-verifiable-language/)

The argument for a "mainstream" verifiable language hinges on bridging the gap between academic proof assistants and daily productivity; if we can achieve machine-checked correctness without sacrificing the ergonomics or ecosystem support we expect from languages like Rust or Go, we could eliminate entire classes of runtime bugs (like null derefs or buffer overflows) at compile time. The real technical hurdle isn't just the type theory—it's the UX of writing proofs that don't feel like a chore, and whether mainstream tooling can keep up with the verification overhead without tanking CI times. It’s a tantalizing prospect if it actually works, but I’m skeptical it’ll displace existing strong-typed languages unless the developer experience is radically better than writing `unsafe` blocks in Rust.
